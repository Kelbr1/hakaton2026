# Алгоритмы и AI-модели CyberBreak 2026

Документ содержит детальное математическое и алгоритмическое описание нейросетевых конвейеров платформы.

---

## 1. Извлечение и предобработка аудиосигнала

Для распознавания речи модель требует монофонический несжатый аудиосигнал с фиксированной частотой дискретизации 16 000 Гц.

Процесс извлечения:
1. Вызов утилиты FFmpeg в режиме прямого декодирования:
   `ffmpeg -y -i <video_file> -vn -acodec pcm_s16le -ar 16000 -ac 1 <audio_file.wav>`
2. Параметры:
   - `-vn`: полное отключение обработки видеодорожки для экономии ресурсов;
   - `-acodec pcm_s16le`: кодирование 16-бит Linear PCM;
   - `-ar 16000`: ресемплинг до 16 кГц;
   - `-ac 1`: сведение всех звуковых каналов в один моноканал.

## 2. Модель распознавания речи: Faster-Whisper

Для перевода речи в текст используется оптимизированная реализация архитектуры Whisper на базе CTranslate2:

### Преимущества Faster-Whisper перед стандартным OpenAI-Whisper:
- Увеличение скорости инференса до 4 раз при снижении потребления оперативной памяти на 50%.
- Поддержка эффективного квантования весов `int8` и `float16`.
- Встроенный детектор речевой активности (Silero VAD), отсекающий длинные паузы, шумы дыхания и тишину.

### Стратегия выбора вычислительного устройства:
1. Проверка доступности GPU: функция `torch.cuda.is_available()`.
2. При наличии CUDA GPU: инициализация модели с параметрами `device="cuda"`, `compute_type="float16"` (или `int8_float16`).
3. При отсутствии GPU: инициализация модели на центральном процессоре `device="cpu"`, `compute_type="int8"`, `cpu_threads=4`.

### Результат транскрибации:
Каждый распознанный фрагмент речи сохраняется с полями:
- `start_time`: время начала фрагмента в секундах (с точностью до сотых);
- `end_time`: время завершения фрагмента;
- `text`: очищенный распознанный текст фрагмента.

## 3. Двухуровневая сегментация текста

Для решения двух разных задач (синхронное воспроизведение субтитров и глубокий контекстный поиск) реализован двухуровневый алгоритм разделения текста:

### Уровень 1: Микросегменты (3-7 секунд)
- Формируются напрямую движком Faster-Whisper на основе пауз в речи.
- Назначение: отображение субтитров в плеере, автоскролл текста вслед за речью лектора, построчная подсветка.

### Уровень 2: Скользящие макроокна (~35 секунд с перекрытием 10 секунд)
- Проблема коротких сегментов: фраза из 5 слов (например, «для этого применяется градиентный») не содержит достаточного семантического контекста для векторного поиска.
- Решение: объединение соседних микросегментов в скользящее макроокно длительностью около 30-45 секунд с перекрытием соседних окон в 10-15 секунд.
- Назначение: сохранение законченной смысловой мысли лектора для последующей векторизации.

## 4. Векторные эмбеддинги: FastEmbed и MiniLM-L12-v2

Для преобразования текста в числовые векторы используется модель `paraphrase-multilingual-MiniLM-L12-v2`:

### Характеристики модели:
- Архитектура: трансформер MiniLM (12 слоев, многоголовое внимание).
- Мультиязычность: качественная поддержка русского и английского языков, корректная обработка технической терминологии.
- Размерность вектора: 384 вещественных числа (384-мерное пространство).
- Среда исполнения: FastEmbed на движке ONNX Runtime (C++ оптимизация, AVX2/FMA инструкции процессора).

### Нормализация векторов:
Все вычисленные векторы нормализуются по евклидовой норме (L2-норма):
`v_norm = v / ||v||_2`

Благодаря L2-нормализации вычисление косинусного сходства между двумя векторами упрощается до скалярного произведения (dot product), что обеспечивает максимальное быстродействие.

## 5. Алгоритм семантического векторного поиска

1. **Входные данные:** текстовый запрос пользователя $Q$, идентификатор лекции (опционально) и лимит результатов $K$.
2. **Векторизация запроса:**
   - Преобразование строки $Q$ в 384-мерный вектор $E_Q$ через модель FastEmbed.
   - Нормализация вектора $E_Q$.
3. **Пакетное сравнение:**
   - Из базы данных извлекаются сохраненные векторы макроокон $M_1, M_2, \dots, M_N$ для выбранной лекции.
   - Выполняется единое матричное умножение средствами библиотеки NumPy:
     `scores = np.dot(macro_embeddings_matrix, query_vector)`
4. **Ранжирование и фильтрация:**
   - Отбор фрагментов с оценкой сходства выше порога релевантности (score >= 0.25).
   - Сортировка по убыванию релевантности.
   - Возврат top-K результатов с привязкой к таймкоду начала фрагмента `start_time` и полным текстом макроокна.

## 6. Генерация аналитических конспектов, оглавления и глоссария

Система поддерживает двухуровневый конвейер суммаризации:

### Вариант А: С локальной LLM через Ollama (Qwen 2.5 / LLaMA 3.2)
1. Текст транскрипта лекции разбивается на смысловые блоки и передается в локальную языковую модель с системным промптом на русском языке.
2. Модель формирует JSON-ответ со структурированными полями:
   - `summary`: детальный Markdown-конспект с заголовками, списками тезисов и выводами;
   - `chapters`: массив глав с названиями, кратким описанием и таймкодами;
   - `glossary_terms`: массив из 5-10 специализированных терминов с определениями и отметкой времени.

### Вариант Б: Встроенный гибридный генератор (Offline Fallback)
1. Если сервис Ollama не запущен, включается внутренний алгоритм:
   - Разбиение текста на смысловые сегменты по частотным маркерам переходов («далее», «рассмотрим», «следующий вопрос», «таким образом»);
   - Выделение ключевых определений с помощью синтаксических шаблонов («это», «представляет собой», «называется», «служит для»);
   - Формирование структурированного конспекта по шаблону академического отчета.

## 7. Интерактивная проверка знаний (AI-Квиз)

1. **Постановка задачи:** сформировать 3-5 контрольных вопросов с 4 вариантами ответа (A, B, C, D) для проверки усвоения материала лекции.
2. **Формирование промпта:**
   - Передача ключевых фрагментов транскрипта в модель с требованием сформировать один однозначно правильный ответ и три правдоподобных дистрактора.
   - Обязательное указание точной секунды `timecode` фрагмента лекции, где лектор объясняет данный факт.
   - Составление текстового пояснения правильного ответа.
3. **Сохранение в базе данных:** тест сохраняется в таблице `LectureQuiz` и отдается клиенту для интерактивного прохождения.

## 8. RAG-ассистент «Вопрос-ответ» (Retrieval-Augmented Generation)

1. Пользователь вводит вопрос в чат по лекции.
2. Векторный поисковый движок находит 3-5 наиболее релевантных макроокон лекции с их таймкодами.
3. Формируется контекстный промпт:
   «Вы локальный ассистент по видеолекции. Ответьте на вопрос пользователя, опираясь исключительно на приведенные ниже фрагменты лекции. Не придумывайте факты. Укажите таймкоды фрагментов, подтверждающих ответ».
4. Модель формулирует лаконичный и точный ответ.
5. Клиентский интерфейс отображает текст ответа и интерактивные кнопки источников `[MM:SS]`, позволяющие мгновенно перематывать видео на подтверждающие цитаты.
