# Архитектура системы CyberBreak 2026

Документ описывает архитектурные решения, модульную структуру и схемы взаимодействия компонентов платформы.

---

## 1. Концепция и Local-first парадигма

Система спроектирована по принципу полной локальной автономности (Local-first & Privacy-first):
- Все этапы обработки видеоматериалов (извлечение звука, транскрибация, вычисление векторных представлений, поиск и генерация артефактов) выполняются непосредственно на рабочей станции пользователя.
- Отсутствуют зависимости от внешних облачных API (OpenAI, Google Cloud, AWS и т.д.).
- Персональные данные, видеозаписи и текстовые расшифровки сохраняются в локальном хранилище.

## 3. Серверные модули (Backend)

Серверная часть реализована на базе Python 3.10+ и FastAPI:

1. `backend/main.py`:
   - Точка входа в приложение и регистрация маршрутов REST API.
   - Управление жизненным циклом приложения (lifespan): автоматическое создание таблиц базы данных и сидирование демонстрационной лекции при первом старте.
   - Раздача статического скомпилированного фронтенда из каталога `frontend/dist`.

2. `backend/ai_engine.py`:
   - Реализует паттерн «Синглтон» для централизованного управления тяжелыми нейросетевыми моделями.
   - Инициализирует модель Faster-Whisper с автоматическим выбором устройства: при наличии CUDA используется GPU с типами данных float16 или int8; при отсутствии GPU происходит плавное переключение на CPU в режиме int8.
   - Инициализирует модель FastEmbed (`paraphrase-multilingual-MiniLM-L12-v2`) на движке ONNX Runtime для быстрого вычисления эмбеддингов без накладных расходов PyTorch.
   - Выполняет векторный поиск на основе нормализованного косинусного сходства через матричное умножение NumPy.

3. `backend/media_utils.py`:
   - Извлечение звуковой дорожки из видеофайлов через FFmpeg с приведением к монофоническому сигналу 16 кГц 16-бит PCM WAV (оптимальный формат для Whisper).
   - Автоматическая генерация постеров (thumbnails) лекции через FFmpeg на отметке 15% продолжительности видео.
   - Скачивание видеоматериалов по внешним ссылкам через библиотеку yt-dlp.
   - Потоковая отдача видеофайлов с поддержкой заголовка `Range` (HTTP 206 Partial Content) для мгновенной перемотки видео любого размера.

4. `backend/llm_service.py`:
   - Интеграция с локальной языковой моделью через HTTP API сервиса Ollama (модели семейств Qwen 2.5, LLaMA 3.2).
   - Реализация гибридного резервного генератора (offline fallback): если сервис Ollama не запущен или недоступен, генерация структурированного конспекта, глав, глоссария и тестовых вопросов выполняется встроенными алгоритмами на основе анализа текста и частотных распределений.

5. `backend/models.py`:
   - Декларативное описание схемы базы данных с использованием SQLModel.
   - Описание Pydantic-схем валидации входных запросов и сериализации ответов API.
   - Функции хеширования паролей (PBKDF2 SHA-256 с индивидуальной солью) и генерации сессионных токенов.

## 4. Схема базы данных

База данных SQLite содержит 10 связанных таблиц:

- `Lecture`: основная сущность лекции (название, путь к видео, аудио, постеру, длительность, статус обработки, ссылка на категорию).
- `LectureSegment`: микросегменты речи (3-7 секунд) с точными временными метками `start_time` и `end_time` для построчных субтитров.
- `LectureMacroSegment`: скользящие макроокна (~35 секунд с перекрытием 10 секунд) и их векторные эмбеддинги (384 float числа в бинарном формате BLOB) для смыслового поиска.
- `LectureChapter`: структурированные главы оглавления с таймкодом начала и описанием.
- `GlossaryTerm`: специализированные термины, их определения и таймкод первого упоминания в лекции.
- `LectureQuiz`: сохраненные интерактивные тесты для проверки знаний с вариантами ответов и пояснениями.
- `LectureNote`: персональные заметки пользователя с жесткой привязкой к секунде видео `timecode`.
- `User`: учетные записи пользователей (имя, логин, соль, хеш пароля, роль).
- `Category`: пользовательские категории лекций с цветовыми идентификаторами Apple Pro.
- `UserFavorite`: таблица связей лекций, добавленных в раздел избранного.
- `UserSessionToken`: токены авторизации пользователей для сохранения сессий.

## 5. Клиентская архитектура (Frontend)

Клиентская часть построена на стеке React 18, TypeScript и Vite:

- **Дизайн-система Liquid Glass:** многослойный стеклянный интерфейс с эффектом размытия фона (`backdrop-blur`), неоновыми градиентами и адаптивными контрастными границами для темной и светлой темы.
- **Модуль Workspace:** центральный экран работы с лекцией, объединяющий плеер, интерактивный таймлайн закладок, оглавление, конспект, квиз, синхронный транскрипт, поиск и RAG-чат.
- **Синхронизация состояния:** непрерывное сопоставление текущей секунды видео с активным сегментом транскрипта, активной главой оглавления и ближайшими заметками.
